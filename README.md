# Gym 会员办卡订单管理后台

面向连锁健身房的会员办卡订单管理后台，用于登录后台、新建订单、查询和筛选订单、续卡、撤单，以及为财务导出可对账的订单数据。

当前已完成 React 18 + JavaScript 工程迁移、基础工具链配置、页面视觉 Demo，以及订单核心业务纯函数和单元测试。登录、订单列表、新建订单、404 与后台布局均可预览，请求层和页面业务联动尚待实现。完整需求基线见 [docs/REQUIREMENTS.md](./docs/REQUIREMENTS.md)。

## 启动步骤

- Node.js `20.19+`、`22.13+` 或 `24+`

## 请求层与状态管理设计简述

### 请求层

- 在 `src/api/` 创建统一 Axios 实例，通过环境变量配置 `baseURL`。
- 请求拦截器从登录状态中读取 token，注入 `Authorization: Bearer <token>`。
- 响应拦截器统一转换错误并调用 Ant Design Message 提示。
- 收到 401 时调用 Zustand store 的登出动作，清理本地 token，并导航到 `/login`。
- Mock 层保持异步接口形态，在内存中维护至少 30 条订单；查询、新建、续卡和撤单均通过同一 API 边界完成，使未来替换真实后端时页面改动最小。

### 状态管理

- Zustand 只管理真正跨页面的客户端状态：token、当前用户名及登录/退出动作。
- 登录成功后将 mock token 和用户名保存到 `localStorage`；刷新页面时恢复登录状态与用户名。
- 列表查询条件、分页、弹窗和表单状态优先留在对应页面，避免把短生命周期 UI 状态塞进全局 store。
- 订单数据以 Mock API 为唯一数据源；写操作完成后重新查询，避免页面缓存与内存数据不一致。

## 订单状态约定

```text
待审核 → 待制卡 → 待寄卡 → 已完成 → 已到期
              └────────────→ 已取消
```

- “进行中”是筛选分组，包含待审核、待制卡、待寄卡。
- 续卡仅允许已到期订单；成功后累加年限并回到待审核。
- 撤单仅允许待制卡、待寄卡订单；成功后变为已取消。
- 默认按创建时间降序排列，最新订单显示在最前面。
- 新建订单的初始状态为待审核。
- 订单金额表示累计购卡费用；续卡成功后将本次续卡费用累加到原订单金额。
- 列表中的订单金额为空或 `null` 时显示 `--`；续卡累计时按原金额 0 元计算。

## 开发过程中遇到的最难问题及解决过程

当前最难的问题是把存在歧义的自然语言需求转为一致、可验证的数据和交互规则。例如“创建时间升序”与“最新创建订单显示在最前面”互相冲突；批量续卡没有说明费用是单笔还是合计；导出权限也没有给出明确状态范围。

解决过程：

1. 将确定内容整理为 [需求基线](./docs/REQUIREMENTS.md)，统一状态和验收口径。
2. 将不确定内容改写为可以由业务方直接回答的问题，不在代码中隐藏猜测。
3. 对必须先落地的部分写出逐条假设，并选择可替换的实现边界。
4. 用 Mock API 集中处理业务规则，页面只负责输入和反馈；业务确认后只需修改规则层。
5. 通过开发日志和 Git 暂存内容保留变更痕迹，由用户检查后手动提交。

## Part 5：CSV 导出澄清问题

收到“给财务导出订单数据，并限制部分状态”的需求后，希望向业务方确认：

1. 导出的是当前页、勾选订单，还是当前筛选条件下的全部订单？
2. 哪些订单状态允许导出，哪些状态必须禁止？限制的业务或合规原因是什么？
3. 是否存在财务、店长、普通员工等角色差异，不同角色的导出范围是否不同？
4. CSV 需要包含哪些字段，字段顺序和表头名称是否有固定模板？
5. 是否需要导出手机号、备注等个人信息；若需要，是否要脱敏？
6. 金额需要货币符号吗？应输出数值还是带千分位的展示文本？
7. 空金额、零金额、异常金额分别如何展示和处理？
8. 导出是否沿用列表中的订单号、会员姓名、状态等筛选条件？
9. 是否需要额外的日期范围筛选，以及使用创建时间、完成时间还是支付时间？
10. 是否要求记录导出人、导出时间、筛选条件等审计信息？
11. CSV 使用什么字符编码，是否需要兼容 Windows Excel 中文显示？
12. 文件名是否有固定规则，是否需要包含门店、日期或操作人？
13. 单次最大导出量是多少，大数据量时是否需要提示或分批处理？
14. 没有符合条件的数据时，是阻止下载并提示，还是生成只有表头的文件？

## Part 5：已确认的实现假设

业务方已确认以下导出实现口径：

1. 导出当前筛选条件下的全部符合条件订单，不受表格当前页限制，也不依赖勾选状态。
2. 仅“已完成”和“已到期”订单允许导出。
3. 不导出手机号和备注。
4. 导出沿用当前 Tab、订单号和会员姓名筛选条件，再自动排除不可导出的状态。
5. 金额统一输出为带千分位、保留两位小数的文本，例如 `12,000.00`；CSV 必须正确转义其中的逗号。
6. CSV 使用 UTF-8 BOM。
7. 没有可导出订单时不生成文件，并提示当前没有符合条件的数据。
8. 导出字段固定为：订单号、会员姓名、购卡年限、订单金额、状态、创建时间。
9. 订单金额为空或 `null` 时导出为 `0.00`。
10. 文件名格式为 `健身房订单_YYYYMMDD_HHmmss.csv`。
11. 创建时间格式为 `YYYY-MM-DD HH:mm:ss`。

## 其他已确认实现规则

- 登录表单的账号和密码仍需非空；任意非空组合均登录成功。
- 已登录访问 `/login` 时跳转 `/orders`；根路径 `/` 根据登录状态跳转 `/orders` 或 `/login`。
- 新订单金额不享受折扣；只有单次续卡 5 年及以上按 8 折计费。
- 批量续卡弹窗同时展示单笔续卡费用和本次批量续卡总费用。
- 批量续卡包含无效订单时阻止整批操作，并列出所有无效订单号。
- 批量撤单包含无效订单时阻止整批操作，并列出所有无效订单号。
- 批量续卡和批量撤单支持跨分页保留勾选记录。
- 跨页选择仅在相同状态 Tab 和搜索条件下保留；切换 Tab 或执行新搜索时清空。
- 已到期订单由 Mock 初始数据提供，不实现自动到期。
- 不提供手动订单状态推进功能。
- 页面适配常见桌面和平板宽度。
- 使用 Vitest 为金额计算、状态权限、筛选和 CSV 转义补充单元测试。
- 手机号仅支持中国大陆 11 位号码，正则为 `/^1[3-9]\d{9}$/`。
