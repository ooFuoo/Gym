# 会员办卡订单管理后台需求基线

本文档整理当前已确认的产品与工程需求，作为后续实现和验收的依据。存在歧义的部分应以 README 中记录的澄清问题与实现假设为准，并在业务方确认后同步更新。

## 1. 技术栈

| 类别 | 要求 |
| --- | --- |
| 框架 | React 18 |
| 构建 | Vite |
| 路由 | React Router v7 |
| UI 组件库 | Ant Design v5 |
| HTTP 请求 | Axios |
| 全局状态 | Zustand |
| 语言 | JavaScript |
| 样式 | 不限，可使用 CSS Modules、SCSS 或 Tailwind |
| 可选库 | dayjs、ahooks 等按需引入 |
| 工程化 | ESLint + Prettier |

## 2. 业务与状态模型

系统用于连锁健身房跟进会员办卡订单。

标准流程：

```text
待审核 → 待制卡 → 待寄卡 → 已完成 → 已到期（会员卡到期未续费）
              └────────────→ 已取消（符合撤单条件时）
```

状态集合：待审核、待制卡、待寄卡、已完成、已到期、已取消。其中“进行中”是查询分组，包含待审核、待制卡、待寄卡，不是独立订单状态。

## 3. 登录、路由与后台布局

- 路由包含 `/login`、`/orders`、`/orders/new`，其余路径显示 404。
- 后台布局包含左侧菜单、顶部栏、面包屑和内容区。
- 左侧菜单提供“订单列表”和“新建订单”。顶部栏显示当前用户名和退出入口。
- 登录账号和密码均为必填项，任意非空组合均模拟登录成功；登录后将 mock token 写入 `localStorage`，登录态由 Zustand 管理。
- mock token 和用户名均保存到 `localStorage`，刷新页面后恢复登录状态与用户名。
- 已登录访问 `/login` 时跳转 `/orders`。
- 根路径 `/` 根据登录状态跳转：已登录进入 `/orders`，未登录进入 `/login`。
- 未登录访问受保护页面时跳转 `/login`；退出时清除登录态并返回登录页。

## 4. 请求层与 Mock 数据

- 创建 Axios 实例并配置 `baseURL`。
- 请求拦截器注入 `Authorization: Bearer <token>`。
- 响应拦截器统一展示错误；遇到 401 时清除登录态并跳转登录页。
- 准备不少于 30 条初始订单，覆盖所有订单状态。
- 列表接口支持分页、状态分组、订单号精确匹配、会员姓名模糊匹配和创建时间排序。
- Mock 服务支持查询、新建、续卡、撤单等写操作；数据保存在内存，刷新页面后可重置。

## 5. 订单列表

### 查询与展示

- 状态 Tab：全部、进行中、已到期、已完成、已取消；切换 Tab 后回到第 1 页并重新查询。
- 搜索字段：订单号精确匹配、会员姓名模糊匹配。
- 表格字段：订单号、会员姓名、购卡年限、订单金额、状态、创建时间、操作。
- 默认按创建时间降序排列，最新创建的订单显示在最前面。
- 金额使用千分位和两位小数；`0` 显示为 `0.00`，空值或 `null` 显示为 `--`。
- 状态使用有区分度的彩色 Tag 展示。

### 续卡

- 只有已到期订单可续卡，支持批量续卡和单行续卡。
- 批量选择中存在不符合条件的订单时，阻止整批操作，并列出所有不符合条件的订单号。
- 续卡年限必填，必须是 1～10 的整数。
- 每笔续卡基础费用为“续卡年限 × 1200 元”；单次续卡 5 年及以上按 8 折计费。
- 批量续卡弹窗同时展示单笔续卡费用和本次批量续卡总费用。
- 订单金额表示累计购卡费用；成功后累加购卡年限和本次续卡费用，并将状态改为待审核。原订单金额为空或 `null` 时按 0 元参与累计。

### 撤单

- 只有待制卡、待寄卡订单可撤单。
- 操作前二次确认，并列出将撤销的订单号。
- 批量选择中存在不符合条件的订单时，阻止整批操作，并列出所有不符合条件的订单号。
- 成功后订单状态改为已取消。

## 6. 新建订单

- 会员姓名：必填，2～30 个字符。
- 联系手机号：必填，仅支持中国大陆 11 位手机号码，正则为 `/^1[3-9]\d{9}$/`。
- 购卡年限：必填，1～10 的整数。
- 办卡费用：只读，按“购卡年限 × 1200 元”自动计算。
- 备注：可选，最多 200 字。
- 新订单初始状态为待审核。
- 提交成功后提示并跳转订单列表，新订单可立即查询到。

## 7. CSV 导出

- 列表页提供前端 CSV 导出，不依赖后端生成文件。
- 导出当前筛选条件下跨分页的全部符合条件数据。
- 只有已完成、已到期订单允许导出。
- 不导出手机号和备注。
- 导出字段为：订单号、会员姓名、购卡年限、订单金额、状态、创建时间。
- 金额使用千分位并保留两位小数。
- 订单金额为空或 `null` 时统一导出为 `0.00`。
- 文件使用 UTF-8 BOM。
- 文件名格式为 `健身房订单_YYYYMMDD_HHmmss.csv`。
- 创建时间格式为 `YYYY-MM-DD HH:mm:ss`，页面与 CSV 保持一致。
- 没有符合条件的数据时提示用户，不生成下载文件。

## 8. 其他已确认约束

- 不提供手动订单状态推进功能。
- 已到期订单仅由 Mock 初始数据提供，不实现自动到期。
- 页面适配常见桌面和平板宽度。
- 批量续卡和批量撤单支持跨分页保留勾选记录。
- 跨页选择仅在相同状态 Tab 和搜索条件下保留；切换 Tab 或执行新搜索时清空已选记录。
- 使用 Vitest 为金额计算、状态权限、筛选和 CSV 转义补充单元测试。
- 不擅自增加需求，不提前实现未确认设计，不引入未要求的第三方库。

## 10. 推荐开发顺序

1. 将空白骨架迁移为 React 18 + JavaScript，并配置 Vite、ESLint、Prettier 和测试脚本。
2. 定义订单状态、金额计算、状态权限和筛选等纯业务规则，先完成对应单元测试。
3. 实现可写内存 Mock 数据与 Axios 请求层，包括 token 注入、统一错误处理和 401 行为。
4. 实现 Zustand 登录态、登录页、路由守卫、404 页面和后台布局。
5. 实现订单列表的查询、Tab、搜索、分页、排序、金额与状态展示。
6. 实现单行/批量续卡和批量撤单，并验证整批阻止规则。
7. 实现新建订单表单及提交后跳转、回查。
8. 实现 CSV 导出、转义、权限过滤与无数据反馈。
9. 完成桌面和平板适配、全流程联调、构建检查和文档收尾。
